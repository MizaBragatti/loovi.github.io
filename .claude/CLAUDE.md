Regras de uso eficiente
Faça somente o necessário para resolver a tarefa solicitada.
Não analise o projeto inteiro sem necessidade.
Comece pelo arquivo ou área diretamente relacionada ao problema.
Só leia outros arquivos quando forem necessários para entender ou corrigir o problema.
Não faça refatorações, melhorias ou mudanças que não foram solicitadas.
Não crie arquivos novos se puder resolver usando os existentes.
Não repita código ou explicações desnecessariamente.
Antes de alterar código, identifique a causa do problema.
Faça a menor alteração possível que resolva o problema.
Após alterar, informe apenas:
O que foi alterado.
Por que foi alterado.
Se existe algum ponto que precisa ser testado.
Não explique conceitos básicos quando eu não pedir.
Se a tarefa estiver clara, execute-a diretamente sem fazer perguntas desnecessárias.
Se precisar investigar mais arquivos, faça isso somente quando necessário.
Priorize precisão e simplicidade em vez de mudanças extensas.
